# NSE F&O Signal Bot — V3.0 NORMAL + ORB + MEX

## Release profile

V3 is an incremental redesign of the V8.1 codebase. It retains the existing Upstox feed,
closed-candle cache, WebSocket partial-candle builder, instrument master, option-chain
picker, structural risk validation, PostgreSQL persistence, Telegram outbox and FastAPI
health/diagnostic endpoints. It does not submit, modify or cancel broker orders.

The Render blueprint selects `STRATEGY_MODE=V3`, `V3_PROFILE_ENABLED=true`,
`ALERT_SCORE_MIN=7.0`, and `PAPER_MODE=true`. `V3` maps to the independent three-engine
scanner path. `STRATEGY_MODE=SIMPLE` remains the rollback path; `STRATEGY_MODE=LEGACY`
uses the prior multi-engine threshold profile.

## Engines

### NORMAL (50 configured stocks, plus supported indices)

- 5-minute EMA 9/21, session VWAP, RSI 14, ADX/DMI 14, ATR 14, RVOL 20.
- CALL: EMA9 > EMA21, above VWAP, RSI >= 50, ADX >= 25, +DI > -DI.
- PUT: EMA9 < EMA21, below VWAP, RSI <= 50, ADX >= 25, -DI > +DI.
- RVOL >= 1.2 when usable. Index/other unavailable volume is reported as unavailable rather
  than fabricated.
- Trend continuation, pullback/resumption and fresh breakout triggers. A fresh EMA cross,
  MACD, or a mandatory high-body candle is not required. MACD is diagnostic only.
- Entry extension guard: 1.5 ATR from EMA9/trigger context. 15-minute trend is retained as
  context for scoring/diagnostics and is not used as a veto in the V3 profile.

### ORB (100 configured stocks)

- First three completed 5-minute candles (09:15–09:30 IST) form ORH/ORL.
- No signal before 09:30. Same-underlying levels, fresh break, >=0.65 ATR clearance,
  body >=55%, close in the outer 25%, and <=1.5 ATR extension.
- RVOL >=1.5 is a preferred quality diagnostic, not a hard gate. Retest is optional.
- Per-symbol state, daily opening range and duplicate/re-arm lifecycle remain independent.

### MEX (100 configured stocks)

- Compression release / range expansion and continuation impulse.
- ADX >=18, directional impulse >=0.65 ATR, range expansion >=1.8x recent median,
  fresh local-boundary break, strong close and <=1.8 ATR extension.
- RVOL >=1.5 is preferred context, not a hard gate. MACD, RSI and VWAP are diagnostics;
  MEX does not inherit NORMAL's full set of filters.

## Live and closed-bar behaviour

- REST bootstraps and recovers candle history; Upstox WebSocket ticks build a separate partial
  candle. Partial data never enters finalized candle history.
- NORMAL, ORB and MEX have independent live trigger evaluation. Candidate timestamp, trigger,
  feed freshness, entry displacement and shared risk/option checks are validated before alert.
- A live provisional alert is explicitly labelled; the finalized candle remains authoritative.
- The current implementation uses the existing shared scanner's engine priority when multiple
  strategies trigger on one underlying/candle (ORB, then MEX, then NORMAL) to avoid duplicate
  or contradictory notifications.

## Risk, contract and alerts

- Existing option picker validates the current instrument master, expiry, CE/PE mapping,
  executable ask, bid/ask spread, OI/volume in lot units, quote freshness and Greeks delta.
- Structural underlying stop is mapped to premium using delta; stops outside the configured
  ATR risk envelope are rejected rather than silently tightened. `MIN_RR_T1=1.5` in V3.
- Targets are 1.5R, 2.5R and 4R (premium and underlying levels). TP3 is informational in
  the Telegram message; the existing tracker continues to manage its currently supported
  TP1/TP2 lifecycle. It is not represented as a fully tracked TP3 exit state yet.
- The existing Telegram outbox retries delivery with dedupe protection. The bot is signal-only.

## Universe and data integrity

- NORMAL list is fixed at 50. ORB and MEX each have separate fixed 100-name lists.
- Bootstrap validates the lists against the current NSE_FO instrument master and surfaces
  missing/unavailable symbols; it does not invent instrument tokens or pad lists.
- Stock and index volume treatment remains separate. No synthetic index volume is created.

## Environment and rollout

The included `render.yaml` sets the V3 mode and keeps `PAPER_MODE=true`. Before production
alerts, attach a persistent Render PostgreSQL database, set Upstox read-only credentials and
Telegram credentials, verify `/diagnostics` feed/subscription/history status, then run replay
and paper-forward validation. Do not switch `PAPER_MODE` off as a shortcut: the code has no
order-placement path, and paper mode should remain enabled during validation.

Important configurable values include:

| Setting | V3 default | Purpose |
|---|---:|---|
| `STRATEGY_MODE` | `V3` in Render | Enables NORMAL + ORB + MEX route |
| `V3_PROFILE_ENABLED` | `true` in Render | Enables V3 NORMAL/risk thresholds |
| `ALERT_SCORE_MIN` | `7.0` in Render | Shared 10-point publication floor |
| `NORMAL_ADX_MIN` | `25` | NORMAL ADX floor |
| `MEX_MIN_IMPULSE_ATR` | `0.65` | MEX directional impulse |
| `MEX_MIN_RANGE_RATIO` | `1.8` | MEX range expansion |
| `MEX_ORB_CLEARANCE_ATR` | `0.65` | ORB breakout clearance |
| `MEX_ORB_BODY_MIN` | `0.55` | ORB candle body fraction |
| `MEX_ORB_CLOSE_POS` | `0.75` | ORB close near candle extreme |
| `MIN_RR_T1` | `1.5` | Minimum remaining reward/risk to T1 |

## Validation status and known limits

- `python -m compileall -q .` is required.
- Full pytest suite is the regression gate; GitHub Actions must run on the pushed repository
  before calling the release CI-verified.
- Historical replay currently uses underlying candles. It cannot prove option-premium P&L,
  theta/IV effects, live option-chain fills, or tick-level slippage without timestamped option
  chain history and quote/trade data.
- No accuracy, profitability, win-rate or lower-stop-hit claim is made by this code change.
- TP3 outcome tracking, explicit per-strategy signal records when multiple engines trigger
  simultaneously, and a true exchange-side order-execution prohibition audit remain separate
  acceptance items. No execution code is intentionally introduced in this release.
